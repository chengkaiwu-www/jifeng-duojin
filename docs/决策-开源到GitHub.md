## 三、⚠️ 顺带纠正一个常见误解

> **"把源码传上 GitHub，会不会影响软著申请 / 游戏过审？"**

- **不影响软著**。软著保护的是"你写的这份代码"，公开传播不改变著作权归属（你仍是著作权人）。
- **不影响过审**。2026-03 起审查趋严，要求是「源码**真实可运行**且**本人改过**」—— 公开与否不在审查项里。
- 唯一实际影响：**别人可以抄你的玩法**。但你的目标是「能讲的作品」而不是赚钱 ⇒ **这不构成损失**，反而是作品被看见的代价与价值。

## 四、推之前的三步（照着做即可）

```bash
cd "<项目根目录>"

# 1. 初始化仓库（.gitignore 已就绪,它会挡住 .workbuddy/ 与软著材料）
git init
git add -A
git status            # ← ★ 关键一步:肉眼扫一遍文件清单,
                      #   确认没有 .workbuddy/ 、没有 docs/软著-截图/ 、没有 *.pdf

# 2. 确认关键目录确实没被加进来(输出应为空)
git status --short | grep -E "\.workbuddy|软著|\.pdf" || echo "✅ 干净"

# 3. 提交
git commit -m "feat: 疾风夺金 v1.0.0 —— 竖版跑酷小游戏(原生 Canvas + 微信云开发)"
```

> 🔑 **`git status` 那一眼是整个流程里最重要的一步。** `.gitignore` 挡的是"已知项"，
> 而"没报出来 ≠ 真的没问题" —— 只有人眼核对过文件清单，才敢按提交。

### 推送前建议再自检一次（一条命令）

```bash
# 列出即将提交的所有文件,人工确认
git ls-files | head -100
```

若发现不该进的，**不要**用 `git rm --cached` 逐个删（容易漏），直接补进 `.gitignore` 后重来。

## 五、如果一定要连历史一起清（已经误推过才需要）

