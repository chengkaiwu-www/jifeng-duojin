# 决策 · 这个游戏能赚钱吗（哪怕一点点）

> 2026-10-05 定。回答「可以赚钱吗，哪怕只是一点点」。
> **结论：能赚，但只有一条路（广告）；在"上线后放养"的策略下，期望收入 ≈ 0–几十元/月。不要为钱改计划。**

---

## 一、能，但只有一条路

个人主体小游戏的能力边界：

- ❌ **不能开通虚拟支付** → 做不了内购、充值、卖皮肤收钱。凡是"用户直接付钱"的模式，个人主体**全部做不了**。
- ✅ **可以开通流量主** → 激励视频 / 插屏 / Banner，按广告曝光分成。

⇒ 唯一的钱来自广告。公式：

```
月收入 = 日活 × 人均广告展示次数 × eCPM ÷ 1000 × 30
```

其中 **eCPM 你控制不了**（平台与广告主定价），**能控制的只有流量**——
而流量需要推广，恰好是范围冻结里砍掉、且"上线后放养"不会去做的那部分。

## 二、门槛：累计 UV > 500（官方旧页写 1000 —— 以后台实际提示为准）

**小游戏**累计独立访客(UV) **> 500**，且无严重违规记录，即可申请流量主。
达不到 = **收入恒为 0**（连广告位都建不了）。

⚠️ **这个数字存在两套口径，必须说清**（2026-10-05 核实）：

| 口径 | 来源 | 可信度 |
|---|---|---|
| **500** | 腾讯广告**官方培训材料**（2024-06）原文：「小程序累计独立访客 (UV) > 500」；百度百科 / 爱企查 / 多位 2026 年实测开发者均写 **小游戏 500、非游戏类小程序 1000** | 高（**两个类目门槛本来就不同**） |
| 1000 | 微信官方开发者社区《流量主开通流程》页：「小游戏累计独立访客(UV)1000以上」 | 中——该页**自带免责声明「知识库内容非实时更新，可能已过期」** |

⇒ **按 500 做规划，上线后以「推广 → 流量主」页面实际提示为准。**
这个差别对你很实际：冷启动一次性放 400–800 UV ⇒ **门槛 500 的话，冷启动当天基本就摸到了**；若后台显示 1000，就得靠分享补一半。

⚠️ 是**累计**独立访客，不是日活。这个门槛比"日活 500"容易得多——但门槛后面的池子里有没有水，是另一回事。
⚠️ **资格次日刷新** —— 达标当天按钮不会马上亮，要等第二天。

## 三、微信给你多少冷启动量（决定成败的关键事实）

来源：Cocos 中文社区一位**同时上架过微信与字节**的开发者实测（2021，至今仍是业内共识口径）：

- 微信：**需要你自己申请**冷启动量 → 约 2 天后放量 → 渠道是游戏栏目瀑布流中一个叫「新品推荐」的小版块，**藏得很深**
- 放量规模：**一次性几百**（运气好 700–800，差 400–500）
- ★ **只给 24 小时的量，多一秒都不给**
- 放完之后：「每天的自然量可能就几个，甚至一个没有」

对照字节：无需申请、自动给几千到七八千，之后每天还有一两百。**微信是几个主流平台里冷启动最抠的。**

⇒ 推论：**累计 UV 500 大概率能靠冷启动一次就摸到**（起步就有 400–800），
但**摸到之后就没有水了**：日活会掉到个位数。

## 四、收入量级（个人主体 / 纯广告，参考 ARPDAU ≈ ¥0.15）

| 日活 | 月广告收入 | 现实性 |
|---|---|---|
| 3 | ≈ ¥14 | ★ 最可能 |
| 20 | ≈ ¥90 | 朋友圈 / 群分享之后 |
| 100 | ≈ ¥450 | 需要一点自然量 |
| 500 | ≈ ¥2,250 | 需要游戏圈 / 达人推 |
| 2,000 | ≈ ¥9,000 | 小爆款 |
| 10,000 | ≈ ¥45,000 | 爆款 |

行业参考：**激励视频 eCPM 50–150 元**（爆款峰值可到 280–300），插屏中等，**Banner 只有 5–20 元**。
⇒ 广告位要**优先做激励视频**（复活、金币翻倍、开局加成都是天然植入点），Banner 只当添头。

## 五、钱怎么到手（小额几乎全额到手）

官方结算规则（微信广告）：

- **次月 1 日**结算上月 1–15 日收入；**次月 15 日**结算 16–月末收入（遇法定节假日顺延）
- ★ **无最低金额门槛、无需手动提现**，自动打到你绑定的银行卡
- 个人主体：**无需邮寄发票**，腾讯**代扣代缴个税**、并代征增值税及附加税费

税务口径：

- 增值税 + 附加：**单次劳务收入 ≥ 500 元**才起征，综合税率约 6%（12% 减半征收）
- 个税：劳务报酬所得，**每次收入 ≤ 800 元基本不产生个税**

⇒ **月入 ≤ 800 元时，几乎全额到手。** 所以"哪怕只是一点点"——那点钱是真能拿到的，且不麻烦。

## 六、结论与建议

**判断：在"上线后放养"的策略下，期望收入 ≈ 0 到几十元/月。**

不是因为游戏做得差。eCPM 由平台和广告主决定，**与你的代码质量、玩法设计基本无关**；
而是因为 **IAA 的收入结构里流量是唯一变量，而流量需要持续推广**——
推广既在范围冻结之外，也和"上线后放养"直接冲突。

**所以：不要为了赚钱改计划。** 理由不是"赚不到"，而是**投入产出比**：
要把月收入从 ¥20 变成 ¥2,000，需要的是持续买量 / 运营，那是一条真正的工作量，
而不是"顺手加个广告"。**几十块的预期回报，不值得换掉"寒假上线后就不管了"这个安排。**

**但如果只是想"顺手赚一点点"，下面三件事不改计划也能做（全部是一次性）：**

1. **上线后立刻申请冷启动量** —— 免费，几百 UV，但**只放 24 小时、过期不补**。
   这是唯一能显著改变累计 UV 的免费动作，**值得定个提醒**。
2. **接激励视频**，位置放"复活 / 金币翻倍"（eCPM 是 Banner 的 5–10 倍）。
   按判据 ①② —— 不新增云函数/集合/页面、不引入持续运营 ⇒ **不算越界**。
3. **ASO 一次性优化**：名称、简介首句塞进玩家真会搜的词。零成本。

**❌ 不建议做的**：微信游戏圈、达人合作、买量 —— 三者都需要**持续运营**，
与放养冲突，且是真正的时间黑洞。

## 七、"零投入"的准确版本：全部现金支出

我此前对你说的"零投入"，**准确的说法应该是**「不用买服务器、不用买量、不用外包美术、不用版号」——
这些才是真正的大钱（几千到几万）。但有**两处会悄悄冒出来的钱**，我之前没有一次讲清：

| 项 | 金额 | 能不能省 |
|---|---|---|
| **微信认证** | **30 元 / 年**（个人主体价） | ✅ **先不交** —— 官方定论（微信开放文档）：「**个人类型…未认证不影响发布上架**」⇒ **现在不做**，代价只有"搜一搜搜不到"+"被分享能力不开"，**上线后随时可补** |
| **云开发**（全服榜 + 云存档） | 免费额度 6 个月，**且小程序上线后第 15 天到期** ⇒ 之后 **19.9 元/月** | ✅ **一行代码省掉**：`config.ENABLE_CLOUD = false` 切纯单机，**0 元**，游戏本体完整可玩，只损失全服榜与云存档 |
| 软著登记 | **0 元**（登记费 2017 年起已取消，线上自助提交） | 本来就免费（代办才收 800–1500，我们自己做） |
| 小程序备案 / ICP 备案 | **0 元** | 免费 |
| 域名 / 服务器 | **不需要** | 小游戏不走这一套（那是网站备案的事） |
| 美术外包 | **0 元** | 造型参数化绘制，零美术资源 |
| 买量 / 推广 | **0 元** | 不在计划内 |

⇒ **总支出可以是 0 元**，而且这是**架构上就设计好的**（"云端可拔"就是为这一刻准备的）。
⇒ **最坏情况也只有 30 元/年**。

⚠️ 但要把账算清：**如果目标只是"几十元/月"，那么 30 元认证 + 19.9 元/月云开发 = 必然净亏。**
所以正确姿势是：

1. **云开发：上线后切单机**（`ENABLE_CLOUD = false`）⇒ 保 0 成本；
2. **认证：先不做**（官方允许）。★ **冷启动量不依赖认证** ⇒ 你 UV 过 500 的主路径不受影响；
   将来真需要"被搜索 / 被分享"时再交 30 元，**随时可补、不影响已上线版本**。

## 八、它真正的价值不在钱

目标是"能讲的作品"，唯一尺子是"能不能在技术评审讲出来"。

一个月几十块的广告费，在技术评审里讲不出任何东西；但——
"四种玩法模式如何用三个正交机制收成纯数据"、"摆动为什么必须由 y 驱动而不是时间驱动"、
"服务端上限校验怎么按模式推导"——**这些能讲**。

**别让几十块的预期回报，污染了一个能讲的作品。**

表态「有几十块就够了」之后，当天把两个激励视频入口**写完并验证**，**默认关闭**。

| 位置 | 改了什么 |
|---|---|
| `js/config/config.js` | 新增 `AD_UNITS.rewarded`（空字符串）+ `AD` 段（复活次数 / 无敌秒数 / 询问倒计时） |
| `js/platform/ad.js` | 新增 `isAvailable()`；`initRewarded()` 的广告位 ID 改为从 config 读 |
| `js/main.js` | 启动时 `Ad.initRewarded()` |
| `js/scenes/game-scene.js` | 新增 `STATE.DYING` + 复活询问面板 + 结算「看视频 · 金币 ×2」按钮 |

### 两个入口的设计取舍

**① 看视频复活**（命归零时）

- ★ **必须在 `endGame()` 之前拦截。** `endGame()` 要写存档、发金币、判成就、上报分数，**全是不可逆的**。
  所以新增了独立的 `STATE.DYING`（世界冻结态），而**不是**在结算面板上做"复活"——
  在结算面板上复活 = 重复发币 = 玩家可以静默刷金币。
- 回 **1 命**（不是回满）：回满会让"续一次"过于廉价，玩家会把它当常规流程走。
- 复活后给 **2.2 秒无敌** + 清掉上方的红块（**保留金块**，让场面像"重新开局"而不是"空场"）。
- **死线模式不给复活**：它是 60 秒限时结算，输赢由**时间**决定；时间不会因为看了广告就往回走。
- ★ **反作弊零风险**：`submitScore` 的 `MODE_LIMITS` 里 classic/gale/rush 的 `maxDuration` 都是 **900 秒**，
  复活延长的那点时长远远够不到；而校验是「每秒上限 × 实际时长」，时长变长只会**放宽**上限，不会误判。

**② 结算「看视频 · 金币 ×2」**

- 只动经济层，不碰玩法规则、不影响单局时长。
- 一局只给一次；点过之后按钮**仍在原位**（变禁用态）—— 凭空消失会让整块按钮区跳一下。
- 翻倍后**重算 `goalHint`**：它写的是"再攒多少就能买"，不重算的话金币涨了、提示还停在原地，读起来像没生效。

### 验证（都跑过）

- 六套自检 **全绿**；**关闭态体检 0 处相撞** ⇒ 证明"接入了但没开启"与接入前逐字节一致。
- 新增 `_overlap-ad.js`（**广告开启态**体检）—— ★ 常规体检**永远覆盖不到**这两个新 UI，因为默认关闭，
  这正是本项目最防备的盲区。结果 0 处相撞；且「死线」场景的文字数与基线结算面板一致，
  **证明死线确实没给复活**。
- 新增 `_ad-behavior.js`：**18 项行为断言全过**。核心是 **"结算恰好一次"**：
  询问期间不结算 / 放弃后只结算一次 / 再点不二次结算 / 复活不产生结算 /
  复活用尽后再次归零直接结算 / 翻倍只翻一次 / 关闭广告后行为回到接入前。
- ★ **注入验证**：把复活拦截摘掉（`requestReviveOrEnd()` 换回 `endGame()`）→ 断言红了 **6 条**，
  且第 2、6 组不受影响 ⇒ **断言有区分度，不是"永远绿的假断言"**。

### 拿到广告位之后要做的三步（顺序不能反）

1. 后台「推广」→「流量主」开通（门槛：**累计独立访客 > 500**，以后台实际提示为准；**资格次日刷新**）
2. **补财务资料（银行卡）** —— 不补，收入结算不了
3. 创建广告位 → 把 adUnitId 填进 `js/config/config.js` 的 `AD_UNITS.rewarded`
   → 把 `ENABLE_AD` 改成 `true` → 提审

> 第 3 步之后**必须跑一次 `_overlap-ad.js` 与 `_ad-behavior.js`** —— 这次是真机验证，
> 因为它俩此前只在打桩环境里跑过。
