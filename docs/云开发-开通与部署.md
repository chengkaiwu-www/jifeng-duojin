# 云开发 · 开通与部署（一次性，约 20 分钟）

> **为什么现在做**：5 个云函数早已写完，不开等于白写；免费额度覆盖到寒假上线，**0 成本**；
> 而且「服务端按模式推导上限卡客户端上报」这段反作弊逻辑，**只有真跑起来才讲得实**。
> 决策推演见 `docs/决策-云开发取舍.md`。

**做完的效果**：控制台那 14 条红字**全部消失** → 主页「游客玩家」变成真实用户 → **全服排行榜**与**云存档**生效。

## 总览：4 步，缺一不可

| # | 做什么 | 在哪 | 耗时 |
|---|---|---|---|
| 1 | **开通云开发环境** | 开发者工具左上角「云开发」 | 5 分钟 |
| 2 | **把环境 ID 填进配置** | 编辑器 `js/config/config.js` 第 19 行 | 1 分钟 |
| 3 | ★ **部署 5 个云函数** | 右键 `cloudfunctions/` 下的每个文件夹 | 8 分钟 |

⚠️ **第 3、4 步是最容易漏的**——只做第 1、2 步，红字会**照旧**（只是错误从"没开通"变成"函数不存在/集合不存在"）。

## 第 1 步 · 开通云开发环境

1. 开发者工具**工具栏**点「**云开发**」（云朵图标）。
2. 首次会弹开通引导：
   - **环境名称**：填 `prod`（或任意，后面能改）
   - **套餐**：选**免费**那一档
3. 开通后自动进入**云开发控制台**。左上角「设置」→「环境设置」里能看到 **环境 ID**（形如 `prod-1a2b3c4d5e6f7g`），**复制它**。
4. 回到编辑器看左侧资源管理器：`cloudfunctions` 后面**不再是「未选择环境」，而是显示环境名** = 关联成功。
   （若没自动关联，右键 `cloudfunctions` 文件夹 → 选择环境。）

> ⚠️ **顺序不能颠倒**：**必须先开通云环境，再右键上传云函数**。
> 反过来做会报「**请在编辑器云函数根目录 (cloudfunctionRoot) 选择一个云环境**」——
> 因为那时**还没有任何环境可选**。这不是配置错，是顺序错。

> ⚠️ **看清是哪一侧的入口**，两者免费规则不同：
> - **微信侧**：40,000 资源点/月，可体验 **6 个月**，之后 19.9 元/月。
> - **腾讯云侧**：仅 3,000 点/月，且「**小程序发布后，环境到期时间变更为上线后第 15 天**」，到期不转付费会**销毁**。
>
> ⇒ **记下开通日期与到期日**，写进日历。

## 第 2 步 · 把环境 ID 填进配置

打开 `js/config/config.js`，第 19 行：

```js
CLOUD_ENV: 'your-cloud-env-id',     // ← 删掉这串占位符，换成你复制的真实环境 ID
```

改成（示例）：

```js
CLOUD_ENV: 'prod-1a2b3c4d5e6f7g',
```

> 这一处是**全项目唯一的云环境配置**。`js/platform/cloud.js` 的 `wx.cloud.init({ env: cfg.CLOUD_ENV })` 读的就是它。
> 想临时退回纯单机：把同文件的 `ENABLE_CLOUD` 改成 `false` 即可（游戏本体完整可玩，排行榜/存档降级本地）。

## 第 3 步 · 部署 5 个云函数 ★

**光有代码不够——必须上传到云端**，否则调用时报「函数不存在」。

在左侧**资源管理器**里，展开 `cloudfunctions/`，对**这 5 个**逐个操作：

```
login        submitScore        getRank        saveArchive        dailySign
```

对每个文件夹**右键** → 选「**上传并部署：云端安装依赖（不上传 node_modules）**」：

| 菜单项 | 说明 |
|---|---|
| **上传并部署：云端安装依赖** | ★ **推荐**。不用本地 `npm install`，云端自动装依赖 |
| 上传并部署：所有文件 | 会把 `node_modules` 一起传，慢且易失败 |

- 首次上传会问「**是否创建并部署**」→ 确定。
- 每个函数上传约 10–30 秒，**等它提示成功再做下一个**。
- 上传成功后，云开发控制台 →「云函数」里应能看到 **5 个**函数，且状态正常。

## 第 4 步 · 建 7 个数据库集合 ★

微信云开发的**集合必须手动预先创建**（本项目云函数里**没有**自动建集合的逻辑），否则报
`errCode: -502005 errMsg: collection not exists`。

云开发控制台 → 左侧「**数据库**」→ 左上角「**+**」（新建集合）——**逐个创建这 7 个**（名字必须**逐字一致**）：

| 集合名 | 谁在用 | 存什么 |
|---|---|---|
| `users` | `login` | 用户档案（openid、昵称、首次登录时间） |
| `user_stats` | `login` / `submitScore` / `getRank` | **全服榜的排序依据**（最高分、总场次等） |
| `scores` | `submitScore` | 每一局的成绩流水 |
| `events` | `submitScore` | 埋点事件 |
| `archives` | `saveArchive` / `dailySign` | 云存档（与本地存档同步） |
| `sign_logs` | `dailySign` | 签到记录 |
| `configs` | `getRank` / `login` | 榜单缓存 / 远程配置（缺失只会降级，不致命） |

### 权限怎么选

**全部选「仅管理端可读写」。**

理由（这是安全的，不是保守）：本项目**客户端从不直接访问数据库** —— 所有读写都在云函数里
（`js/` 与 `openDataContext/` 里**没有任何** `wx.cloud.database()` 调用）。
云函数用的是**服务端 SDK，有管理员权限，不受集合权限限制**。

⇒ 把权限设到最严，等于**关掉客户端直连数据库这条后门**：想拿数据只能走云函数，
而云函数里正好有 `submitScore` 的**按模式每秒得分上限校验**。**反作弊这条线就此闭合。**

## 验证（第 5 步，其实是"看结果"）

1. 回到编辑器，点工具栏「**编译**」（或重新打开项目）。
2. 看**调试器 Console**：
   - ✅ 应出现 `[MG] cloud init ok, env = prod-xxxx`
   - ✅ 那 14 条红色 `errCode: -601034` **应全部消失**
3. 看**模拟器主页**：「游客玩家」应变成真实用户信息。
4. 点「**排行榜**」：应能加载（首次为空榜单 = 正常，说明云函数通了）。

**还有红字？对照下表**：

| 报错关键词 | 含义 | 怎么办 |
|---|---|---|
| **`请在编辑器云函数根目录 (cloudfunctionRoot) 选择一个云环境`** | ★ **最常见的顺序错误**：还没开通云环境，就先去右键上传云函数了。左侧 `cloudfunctions` 括号里会显示「**未选择环境**」 | **回到第 1 步**开通环境；开完该节点会变成环境名 |
| `-601034 没有权限，请先开通云开发` | 环境没开通 / ID 没填 | 回到第 1、2 步 |
| `FunctionName parameter could not be found` / `函数不存在` | 云函数没部署 | 回到第 3 步（漏传了某个函数） |
| `-502005 collection not exists` | 集合没建 | 回到第 4 步（对着表逐个建） |
| `-501007 ... permission denied` | 集合权限设错 | 改成「仅管理端可读写」 |
| 完全没有云相关日志 | `ENABLE_CLOUD` 被关了 | 检查 `js/config/config.js` 的 `ENABLE_CLOUD` 是否为 `true` |

## ⚠️ 上线后的两条路（都不亏）

- **A 保住全服榜** → 到期后转付费 19.9 元/月（约 240 元/年）。
- **B 放养（符合"上线后不管"的目标）** → `js/config/config.js` 里 `ENABLE_CLOUD: false` 一行切纯单机，**0 元**。

> B 之所以可行，是因为架构从一开始就做成「**云端可拔**」：
> `cloud.js` 上报失败会**落本地队列下次补报**、`auth.js` 拿不到登录态就**降级游客态**、boot 会提示「离线模式」。
> **云端是增强项，不是生死依赖。**
